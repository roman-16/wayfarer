# Playtest

`just test` proves the pack boots, every shrine generates and the stronghold ring sits at its radius. It cannot judge how anything looks, sounds or feels. That is the user's, in game.

## Hand the user a checklist

The `finish` skill comes first: its walkthrough finds and fixes what would leave a player stuck, confused or crashed, and its gallery shows the user the change, so this checklist keeps only what play alone shows, the shader, the far view, sound, motion and feel. Pick the items the change touched, and give each as one line: where to go, what to do, what should happen. `just showroom` opens the showroom, where every shrine stands in a row and the compass points at a waymark 750 blocks west of the camp; `/locate structure wayfarer:shrine/<eye>` and `/tp` find the shrines in the natural world next to it. `just play` opens a fresh world in survival, for everything that has to be met the way a player meets it. `python3 scripts/client.py start --state <quest/step> --visible` opens the world at any step of the story, such as `ash/the_door`, with every step before it played. All of them run without shaders, without Distant Horizons (unless started with `far`, which keeps a far view of 1,024 blocks) and at 8 chunks, so shaders, the far view and anything judged by its look in the world are checked in the exported pack: `just pack`, imported into Prism Launcher.

## A blind play

At the bar and at the end of each act, friends who never read `design/` play on the exaroton server with only what the screen shows (`design/production.md`, R3). Nobody who knows the design helps or explains during the play; the designer watches and notes where they hesitate. The server is recorded while they play (Record a play), and the session record shows where the team stalled and how long each step took. Every stall the screen did not explain is a finding for the `finish` skill's walkthrough questions; every "this was boring" goes back to the quest's design. The voice joins the plays only in phase 6, once it is recorded (`design/narration.md`).

## Record a play

`just exaroton` records the account's server into `exaroton/<YYYY-MM-DD_HH-MM>/`, in the repository root and ignored by git. It needs `EXAROTON_API_TOKEN`, which devbox loads from `.env`; never print the token or write it anywhere else. With more than one server on the account, name it: `just exaroton roman168`.

Run it in the foreground with no timeout: it records until the user presses Escape, which kills it and ends the turn; never start it in the background. It prints one line per status change, stream start and reconnect, and waits through an offline server until it boots.

The recorder only reads. Never send console commands, and never call `start`, `stop`, `restart`, `command`, `extend-time`, `logs/share` or any `POST`, `PUT` or `DELETE` endpoint, nor any websocket message but a stream `start`; exaroton makes `start`, `stop` and `restart` plain `GET`s, so reading is not safe by method alone.

| File | Holds |
|---|---|
| `session.json` | At the start: the server object, its RAM, every `server.properties` value and the mods folder with sizes |
| `console.log` | Every console line as it arrives, without ANSI codes; lines carry only `[HH:MM:SS]` |
| `streams.jsonl` | One timestamped JSON line per websocket message: `status` (with players), `heap` (`usage` in bytes), `stats` (`memory.usage`, `memory.percent`), `tick` (`averageTickTime` in ms), `connected`, `disconnected` |
| `polls.jsonl` | Every minute: status, players, region file count, empty region files, region bytes and the Distant Horizons database size, or the error that stopped the poll |
| `latest.log` | The full server log with millisecond timestamps, refreshed every five minutes while the server runs and once when it stops or crashes; while it runs it lags about ten minutes behind |

Every line is written as it arrives, so a session is complete up to the moment it stopped. The tick stream has stayed silent on this server and exaroton reports no CPU usage; "Can't keep up!" lines in `console.log` and `latest.log` measure the server's lag.

## Bring the results back

Every number the user wants changed goes to `balance.toml`, or to the mod's config in `pack/config` when it is another mod's number. Worldgen numbers (shrine and stronghold distances, structure spread) only change new chunks: test them in a fresh world.
